Thrift: Certified Token Savings for LLM Serving

Parveen Kumar Naresh Kumar · University of South Florida · github.com/parveen06naresh/thrift
Abstract. LLM applications overpay in three predictable ways: every request goes to the largest model, repeated questions are paid for again, and prompts carry context the model never needs. Model routing, semantic caching and prompt compression each address one of these, but teams hesitate to deploy them because each trades an unknown amount of quality for cost. We present Thrift, an OpenAI-compatible gateway in which every quality/cost knob is set by Learn-then-Test, giving a finite-sample, distribution-free guarantee that the expected quality loss stays below a user-chosen ε with probability at least 1 − δ. On 8,021 HELM Lite questions with real outputs from three model families, certified routing cuts the GPT-4o bill by 41% for a measured 0.69-point accuracy drop (ε = 2 points). On Quora Question Pairs, the certified semantic cache serves 7.0% of adversarial queries at a 1.73% wrong-answer rate (α = 2%), six times the exact-match hit rate. On multi-document Natural Questions, query-aware compression keeps 98% of a reader model's F1 at 25% of the context tokens, versus 27% for truncation. The gateway adds 1.29 ms median overhead per request.

1. Introduction

Inference cost is now a first-order engineering constraint. Three techniques cut it without touching the model: routing sends easy requests to a cheaper model [FrugalGPT, RouteLLM], semantic caching answers repeated questions from memory [GPTCache], and prompt compression removes tokens the model does not need [LLMLingua]. Each comes with a threshold (a router score, a similarity, a keep-ratio) whose quality cost is usually tuned by eye on a dashboard. A cache that serves a wrong answer to 5% of users, or a router that silently degrades a product, is worse than no optimisation.

Thrift's contribution is engineering plus one idea: treat every threshold as a hypothesis-testing problem and certify it. We use Learn-then-Test (LTT) [Angelopoulos et al. 2021], which turns any per-example loss in [0, 1] on held-out data into a threshold with a PAC-style guarantee. The guarantee needs no model of the scorer or data, so a weak scorer costs savings, never safety. The same family of distribution-free bounds controls latency in the author's earlier serving system Pacer [Naresh Kumar 2026]; Thrift applies it to quality.

2. System

Thrift is a stateless-by-default Python service (Starlette + httpx) that speaks the OpenAI chat-completions API, so any OpenAI SDK, LangChain, or LlamaIndex client works by changing base_url. Tiers are ordered cheapest to strongest and can be any OpenAI-compatible backend, hosted or self-hosted (vLLM, SGLang, TGI). The pipeline per request is:

Cache. A request is split into a scope (tier, system prompt, history, sampling parameters, tools) and a query (the last user message). The exact tier hashes both. The semantic tier embeds the query (signed feature hashing of word and character n-grams; any embedder plugs in) and searches only entries with the same scope, so a hit can never cross system prompts or temperatures. A key-term guard rejects a hit when the numbers or negations differ, the dominant failure of similarity caches ("convert 5 km" vs "convert 50 km"). Errors, truncated answers and n > 1 are never cached.

Compression. Stage 1 normalises whitespace, blank-line runs, invisible characters and decorative rules outside fenced code (lossless). Stage 2 drops paragraphs that repeat verbatim (duplicate RAG chunks). Stage 3 scores sentences of long context against the user's question with BM25 and keeps the best ones up to a keep-ratio, in original order; the question paragraph, system prompt, recent turns and anything containing code are never cut.

Routing. A logistic scorer over hashed unigrams/bigrams and ten structural features (length, digits, maths symbols, code, answer options, question words) predicts the soft label 1 − max(0, qstrong − qcheap). A request goes to the cheap tier when its score is at least λ. If the cheap tier fails, the request falls back to the strong one.

Accounting. Each response carries its tier, cache status, original and sent prompt tokens, its cost, and the baseline: the cost of the same request uncompressed on the strongest tier. These feed Prometheus metrics and a live dashboard. A shadow mode sends a sample of cheap-routed requests to the strong tier as well and logs both answers, producing the labelled data needed to re-certify the router on a team's own traffic.

3. Certifying the knobs

Let λ1, …, λm be candidate settings ordered from safest to most aggressive and Li(λ) ∈ [0, 1] the loss on calibration example i. For each λj in order we test Hj: R(λj) > ε with p-value pj (exact binomial tail for 0/1 losses, Hoeffding–Bentkus otherwise) and stop at the first pj > δ. Fixed-sequence testing controls the family-wise error at δ, so the last accepted setting λ̂ satisfies

P( R(λ̂) ≤ ε ) ≥ 1 − δ

over the draw of the calibration set, for any scorer and any exchangeable data. The losses are: routing, L = 1[s ≥ λ] · max(0, qstrong − qcheap), the quality given up on prompts sent to the cheap model (cheap-model wins are not allowed to offset losses, making the bound conservative); caching, L = 1[sim ≥ τ and the cached answer is wrong]; compression, L = max(0, F1full − F1compressed) for a reader model. All three use the same 60-line implementation.

Routing saves more money than its traffic share suggests (41% of the GPT-4o bill from 21% of questions) because the scorer learns that long reading-comprehension prompts, the expensive ones, are where the small model already matches the large one. Against random routing at the same share, certified routing loses 2–5× less accuracy. The scorer is deliberately small (test AUC 0.56–0.73); the oracle curve shows the headroom a stronger scorer could claim under the same guarantee.

Certification over 200 random calibration/test halvings (120 calibration questions each) is conservative here: at ε = 0.02 and 0.05 F1, for both the per-question and the average loss, Learn-then-Test certifies no compression (keep-ratio 1.0 in every halving, so the bound trivially holds). Answers flip in both directions under compression, so the per-question loss is 6–8% even though mean F1 barely moves, and 120 points cannot separate that from ε. At ε = 0.10 (per-question) it certifies some compression in 23.5% of halvings, with test loss 0.018 and the bound violated in 2.0% (target ≤ 10%). We estimate roughly 3,500 labelled questions are needed to certify a 25% keep-ratio at a 5-point average bound; the shipped default is therefore an empirical setting. The lossless normalisation stage alone removes 0.5% of tokens from all HELM Lite prompts, which are already clean; scraped web pages and PDFs typically carry far more whitespace.

4.4 Overhead

With zero-latency mock upstreams, so that all time is Thrift's own: cache-miss requests add 1.29 ms (p50) / 5.21 ms (p99); cache hits 0.08 ms; long-context requests that are compressed 21.3 ms. One uvicorn worker sustains 211 requests/s at concurrency 32 on a 4-core cloud VM. Upstream LLM latency is typically 300–3,000 ms, so overhead is under 1% for most requests.

5. Limitations

Guarantees hold for exchangeable traffic; distribution shift requires re-certification, which the shadow log supports but does not automate. The bundled router is certified on HELM-style questions, not on any particular product. The default cache embedding is lexical. Compression is validated with an extractive reader rather than a frontier LLM. Costs use list prices.

6. Related work

FrugalGPT [Chen et al. 2023] introduced LLM cascades; RouteLLM [Ong et al. 2024] trains routers from preference data; both report cost/quality curves without a deployment-time guarantee. GPTCache popularised similarity caching with hand-set thresholds. LLMLingua and LongLLMLingua [Jiang et al. 2023] compress prompts with a small LM. Conformal risk control [Angelopoulos et al. 2022] and Learn-then-Test supply the guarantees; conformal methods have been applied to LLM abstention and factuality, and Thrift applies them to the cost knobs of a serving gateway.
